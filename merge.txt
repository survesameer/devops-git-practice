# Git Merge Notes (Interview + Practical)

## 1. What is a Fast-Forward Merge?

A **fast-forward merge** happens when the target branch has **not changed** since the new branch was created. Git simply moves the branch pointer forward without creating a new merge commit.

### Before Merge

```text
main

A ----- B

          \
feature    C ----- D
```

### After Fast-Forward Merge

```text
main

A ----- B ----- C ----- D
```

No merge commit is created.

### Command

```bash
git checkout main
git merge feature
```

### Industry Use Case

You create a feature branch, finish your work quickly, and no one else commits to `main` meanwhile. Git performs a **fast-forward merge**, keeping the history clean and linear.

---

## 2. When does Git create a Merge Commit?

Git creates a **merge commit** when **both branches have new commits** after they diverged. Since Git cannot simply move the branch pointer, it combines the histories with a new merge commit.

### Before Merge

```text
        C ----- D (feature)
       /
A ---- B
       \
        E ----- F (main)
```

### After Merge

```text
        C ----- D
       /         \
A ---- B ---- E ---F
               \   /
                M
```

`M` = Merge Commit

### Command

```bash
git checkout main
git merge feature
```

### Industry Use Case

Two developers work simultaneously:

* Developer A updates the `main` branch.
* Developer B works on a `feature` branch.

When Developer B merges, Git creates a **merge commit** to preserve both development histories.

---

## 3. What is a Merge Conflict?

A **merge conflict** occurs when Git cannot automatically merge changes because the **same part of a file** was modified differently in two branches.

Git pauses the merge and asks you to resolve the conflict manually.

### Industry Example

`main`

```text
Application Version: 1.0
```

`feature`

```text
Application Version: 2.0
```

When merging:

```bash
git merge feature
```

Git reports:

```text
CONFLICT (content): Merge conflict in app.txt
Automatic merge failed.
```

# Hands-on Lab: Create a Merge Conflict

### Step 1: Create a repository

```bash
mkdir git-merge-demo
cd git-merge-demo
git init
```

---

### Step 2: Create a file

```bash
echo "Version 1.0" > app.txt
git add .
git commit -m "Initial commit"
```

---

### Step 3: Create a feature branch

```bash
git checkout -b feature
```

---

### Step 4: Edit the file

```text
Version 2.0 from Feature Branch
```

```bash
git add .
git commit -m "Feature update"
```

---

### Step 5: Switch back to main

```bash
git checkout main
```

Edit the **same line**:

```text
Version 2.0 from Main Branch
```

Commit:

```bash
git add .
git commit -m "Main update"
```

---

### Step 6: Merge

```bash
git merge feature
```

Git reports:

```text
CONFLICT (content): Merge conflict in app.txt
Automatic merge failed.
```

---

### Step 7: Open the file

Git marks the conflict like this:

```text
<<<<<<< HEAD
Version 2.0 from Main Branch
=======
Version 2.0 from Feature Branch
>>>>>>> feature
```

---

### Step 8: Resolve the conflict

Choose or combine the changes, for example:

```text
Version 2.0 (Main + Feature)
```

Then save the file.

---

### Step 9: Complete the merge

```bash
git add app.txt
git commit -m "Resolved merge conflict"
```

The merge is now complete.

# Interview Answer (30 Seconds)

### Q: What is a fast-forward merge?

**Answer:**

> A fast-forward merge occurs when the target branch has no new commits since the feature branch was created. Git simply moves the branch pointer forward without creating a merge commit.

### Q: When does Git create a merge commit?

**Answer:**

> Git creates a merge commit when both branches have independent commits after they diverged. The merge commit combines the histories while preserving both sets of changes.

### Q: What is a merge conflict?

**Answer:**

> A merge conflict occurs when Git cannot automatically merge changes because the same part of a file has been modified differently in two branches. The developer must manually resolve the conflict and then complete the merge.

# Quick Revision

| Concept                | Meaning                            | Merge Commit Created?         |
| ---------------------- | ---------------------------------- | ----------------------------- |
| **Fast-Forward Merge** | Target branch has no new commits   | ❌ No                          |
| **Three-Way Merge**    | Both branches have new commits     | ✅ Yes                         |
| **Merge Conflict**     | Same file/line changed differently | ⚠️ Manual resolution required |

### Key Takeaways

* **Fast-forward merge** = Clean, linear history, no merge commit.
* **Merge commit** = Preserves the history of parallel development.
* **Merge conflict** = Happens when Git cannot decide which change to keep; resolve it manually before completing the merge.
